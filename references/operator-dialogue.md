# 操作者对话与项目引导

本文件用于首次配置、模块选择、项目恢复和需要操作者判断的节点。目标是减少填表负担，同时让重要假设得到明确确认。

## 首次使用

先检查当前工作区是否已有 `.wy/wy.db` 和供应商画像。没有时按以下顺序补齐，只问会阻塞当前模块的问题：

1. 当前要做的模块和具体目标。
2. 产品类别、核心规格/应用和目标市场。
3. 理想客户类型及明确排除项。
4. 可兑现的供应商事实：材质/规格、认证、MOQ、价格边界、交期、产能、案例授权。
5. 发件人身份、公司名称、官网和希望使用的语言/语气。
6. 不允许写入对外内容的声明或尚未确认的信息。

如果用户选择 TikTok 获客，再补问目标国家/语言、账号现状、可拍摄场景、主推 SKU、公开价格边界、承接渠道和负责跟进的人员；按 [tiktok-acquisition.md](tiktok-acquisition.md) 逐阶段指导，不一次要求提交完整内容日历。

用户可以先给不完整信息。把缺失项分成“当前必须”“后续再补”，不要阻塞无关模块。需要保存时，从 `assets/templates/supplier-profile.json` 复制到项目目录；不得把 API 密钥或邮箱密码写入画像。

## 每轮对话

1. 用一两句话复述当前目标和已采用的关键条件。
2. 如果有一个阻塞问题，先问该问题并等待；不要同时问多个不相关问题。
3. 可安全采用默认值时，说明默认值并继续，不让用户逐项确认。
4. 完成阶段后交付：结果、证据/依据、未知项、推荐下一步。
5. 给出少量明确动作，例如“继续找客户”“为前 3 位联系人起草”“修改评分条件”“暂停”，不要要求用户学习内部阶段名。

## 项目恢复

恢复 `.wy/wy.db` 时先运行 `status`、`activation-report` 和 `validate`。向操作者显示：

- 当前产品、国家、阶段和合格客户数。
- 待核验联系人、草稿、待激活客户和 Campaign 状态。
- 校验错误、信息过期或被阻断的联系入口。
- 一项推荐的下一步及推荐理由。

## 人工决策点

以下情况必须停下来让操作者决定：

- 客户身份或同名实体无法可靠区分。
- 背调来源冲突会改变交易决策。
- 产品参数、价格、认证或案例授权不足以支撑对外表述。
- 拟使用低置信度联系入口、敏感个人信息或第三方贸易参考。
- 准备真实发送、表单提交、创建外部 CRM、公开发布或启动自动任务。

操作者修正信息时，优先更新项目数据和证据，不争辩旧结论。记录“用户提供”和“公开来源”的区别。
