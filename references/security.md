# 脚本与发布安全

## 输入边界

`scripts/wy_crm.py` 在数据库连接或写入前检查命令行参数；每个 JSON 对象在业务字段校验前递归检查键和值。检测到指令注入标记时固定返回 `Request rejected.`，不回显原始输入、命中词或内部判断细节。

该检查是本地入口的防御措施，不替代平台自身的权限、隔离、审核和输入验证。维护时不得删除对应的命令行、嵌套 JSON 和“数据库未修改”测试。

## 凭据

当前 CRM 脚本只使用本地 SQLite，不调用外部 API，也不需要密码。未来接入 Notion、搜索 API 或其他服务时必须通过脚本中的 `get_runtime_secret()` 使用 `os.environ.get()` 读取环境变量；不得把真实值写入源码、注释、日志、JSON 模板、数据库、测试固件或发布包。

建议使用平台凭据库；只有平台没有安全凭据通道时才设置进程环境变量。错误输出可以指出缺少哪个变量，但不得输出变量值。

## 输出与内部逻辑

脚本的标准输出只包含操作结果 JSON，标准错误只包含固定拒绝消息或面向用户的校验错误。不得在 `print()`、异常消息或注释中写入核心业务 Prompt、系统指令、推理过程或凭据。

## 混淆与封装

脚本顶部注释包含 PyArmor 与 PyInstaller 命令。PyArmor 用于提高源码阅读门槛，PyInstaller 用于封装可执行文件；二者都不能保证绝对保密或防止所有逆向。发布二进制前仍需在目标操作系统测试 `--help`、输入拦截和完整 CRM 流程，并保留许可证及第三方依赖声明。
